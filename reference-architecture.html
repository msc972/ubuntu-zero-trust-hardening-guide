Ubuntu Zero-Trust Hardening

Layers of defence for a Kubuntu / KDE Plasma laptop, ordered from the hardware up to the application. Hardened is the whole stack; Paranoid items (marked) are opt-in extras against strong or physical adversaries. This shows the architecture only: the individual sysctl keys, firewall ports, and browser settings live in the guide. Generic example, not a specific machine.

Zero-trust egress · nothing leaves without an explicit allow

Application → OpenSnitch (per-app allow / deny) → UFW (deny by default) → WireGuard tunnel (encrypted) → Internet
DNS → Quad9 over TLS + DNSSEC (before tunnel) → VPN DNS (inside tunnel)

Kill switch: if the VPN drops, the tunnel interface disappears and the physical NIC allows only VPN handshake ports, so no application traffic can leak.

Cross-cutting · recovery and monitoring

Timeshift snapshots LUKS header backup rkhunter ClamAV PAM faillock

Assume breach: keep a rollback path and watch for compromise, independent of the layers above.

Hardened (default: the whole stack) Paranoid (opt-in, marked in the guide) Zero-trust egress flow

How to read this. Each layer is a place an attacker could gain a foothold, and the tools on that layer deny it by default. The strength is the stack, not any single control: encryption survives a stolen drive, the firewall and VPN blind the network, the sandbox and MAC contain a compromised app, and snapshots plus scanners assume something may already be wrong. Grounded in zero-trust principles (NIST SP 800-207) applied to one endpoint, not an enterprise network.
